# 实现原理

用户提出的目标是减少校园入口和重复操作。实现选择是本机 Python 适配器、标准 stdio MCP 与 SQLite 快照；这是工程设计，不是学校官方提供的统一接口。

| 位置 | 职责 |
| --- | --- |
| src/mcp_server/server.py | 注册 47 个工具，提供只读查询或人工入口，定义输入和结构化输出 |
| src/service/ | 校验参数、固定查询范围、编排来源、包装结果 |
| src/adapters/ | 读取公开页面或本人会话允许的数据，解析来源结构 |
| src/auth/ | 独立交互认证 CLI 和本地会话存取 |
| src/storage/ | 账号/模块/查询范围下的 SQLite 快照与健康记录 |
| src/domain/ | 业务条目、观测结果和错误模型 |
| test/ | 合成来源、受控时钟、临时数据库及 stdio 回归 |

典型请求是「客户端选工具 → 服务校验 → 适配器读取 → 分类和映射 → 缓存 → 返回数据与证据」。
认证初始化与查询协议分开，MCP 工具不接收密码；公开源不要求个人会话。

成绩、成绩明细、两种课表及考试在MCP入口额外经过`QueryCache`：完整参数、账号和会话指纹隔离，成功非空结果复用60秒，最多32项。强刷绕过结果缓存，命中核验当前SQLite快照并更新数据年龄；激活记忆是独立机制，仍可能省略已激活页面的GET。详见[查询提速](performance.md)。

网页课表经`TimingTransport`只记录请求方法、状态和耗时，不记录请求内容；service按同账号/快照ID读取完整本地条目，使用`semester_credits`的Decimal去重汇总后返回`credit_summary`。汇总不发额外学校请求，来源不完整时不能作为官方学分总量。

## 失败为什么不能变成空列表

来源没有数据、来源拒绝、响应结构变化、只读到部分页面是不同情况。
实现以 ok/partial/unavailable 及 issues、coverage、freshness 表达这些差别；相关路径保留旧成功快照，防止错误响应覆盖好数据。
并非所有历史分支都已全覆盖验证，具体限制见 limitations.md。

## 为什么不并发所有请求

部分教务流程依赖「打开功能页→查询→详情」的会话状态，在线步骤需保持顺序。
离线解析和独立公开来源可分开处理；不同时刷新同一账号会话或并发写同一生产缓存。

教务激活记忆按会话协调整次来源操作，默认开启，可用`ZJGSU_JW_ACTIVATION_MEMO=0`关闭。激活GET传输、HTTP或认证错误立即终止，不能以空POST覆盖旧成功快照；这些锁仅进程内有效。电表按设备复用匿名连接会话，仍每次读取业务页，不把旧余额缓存成当前余额。

SQLite使用WAL与synchronous=FULL，选定服务路径把快照与健康记录放在同一事务；可用`ZJGSU_STORE_JOURNAL=DELETE`回退日志模式。余座和电表另有最小状态JSON契约，不宣称所有新工具已统一旧工具的分页和coverage模型。附件逐文件替换并验证回滚，只有进程内串行，不是跨文件或跨进程事务。

## 发布版本与私人工作目录

GitHub 版本来自固定交付快照，并单独清理私人测试样例、历史个人实例和开发机器路径。
真实 data、学校客户端常量、原始日志、APK/反编译产物及私人交接不包含在仓库中。
因此公开/空会话启动可单独验证，个人查询还需要使用者本机的合法配置和账号。
