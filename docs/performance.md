# 成绩与课表查询提速

更新：2026-10-18。默认 main 已纳入 47 个注册工具，对应 338 项合成回归及本地契约验收。影夜提出成绩、课表查询慢，本页记录已实现的提速与测量边界。

当前实现包括五工具短缓存、教务激活记忆、电表匿名连接会话复用、SSLContext 复用、WAL+FULL 及选定成功事务合并，详见文末当前状态。下方 214/249 项和计时属于 2026-10-16 两轮的历史证据，保留原测量条件；它们不是当前总测试数或当前学校性能承诺。

## 历史第二轮（2026-10-16）：本学期学分的最短路径和实测分段

影夜提供实施方“本学期修读学分”耗时报告，要求检查每段时间和进一步优化。本节记录当时 249 项回归的版本；下方第一轮为 214 项。

### 对原报告的核查

报告列出约11次业务查询，包含预选、网页课表、四次课程库、执行计划及课程、学分要求、重复课表。可确认课程库/计划不是本学期个人修读清单的直接来源，而课表已经投影学分，因此有明确的路线浪费。

原记录没有逐步精确计时：5–6分钟是探索的大致时段；单HTTP0.7–1.0秒、初始化0.07秒和最短0.80秒是实施方文字观测，未附可核查的计时原始记录。不能把余下分钟全部归为模型思考、人的分析或打字，也不能据此承诺WorkBuddy端到端0.8秒。

“一次HTTP”与当时 `fetch_timetable_web` 代码不符：明确学期的普通首查是一次 GET 打开功能页，再一次 POST 读取课表，即**一次 MCP 工具调用、两次 transport 请求**；命中短时缓存时本次零请求。新版激活记忆还可减少重复 GET，见文末当前状态。课程库同样不能把一次工具调用当一次 HTTP。关键词只过滤课程库当前页，未命中不能推断全库不存在；也不能预先断言该页查询必为空。

### 已实现

1. MCP instructions、网页课表、预选与课程库描述明确：本学期修读/选课学分优先`get_timetable_web`，不逐一探查其他来源；改选后或最新要求传`force_refresh=true`。
2. 网页课表直接返回`credit_summary`，对同一个完整SQLite快照聚合，不受当前`limit`分页大小影响，不再让模型重新取数后手算。仅按课程号归并且有效学分一致时累计；重复时段不重复计，缺学分/冲突/缺课程号单列，Decimal精确相加。
3. `known_credit_sum`仅代表**课表可见课程已知学分小计**，不是已得学分或学校官方完整修读总量。来源未证完整、实践课块未包含等限制继续返回，不因算出一个数就消失。
4. 课表来源通过白名单后将数字学分、星期、人数等归一为字符串，符合SDK输出契约；关闭上一轮未覆盖的数值字段类型兼容边界。
5. CLI脚本取消按月份猜学期；无参读取学校selected项，显式传`2026 3`则直接查该学期。首页`limit=500`后只消费本地游标，快照变化或游标异常停止并显示缺口。脚本无参会额外读取当前学期，不能称一次HTTP；脚本本身仍是CLI，WorkBuddy走MCP。

### 现在能测到哪些时间

| 输出字段 | 覆盖范围 |
| --- | --- |
| `performance.source_query.context_ms` | 参数/会话准备；纯本地续页时含续页读取 |
| `performance.source_query.requests[]` | 每个GET/POST调用的耗时、HTTP状态、结果类别 |
| `performance.source_query.http_ms` | 上述请求耗时之和，包含连接/等待来源/读取响应，不拆分DNS/TLS/服务器时间 |
| `performance.source_query.parse_ms` | 来源适配器解析耗时，不含上述请求等待 |
| `performance.source_query.local_result_ms` | 来源读取之后的映射、SQLite记录、包装及同快照汇总 |
| `performance.source_query.total_ms` | 此次底层service调用总耗时 |
| `performance.current_call.handler_ms` | 当前MCP处理函数进入到结果封装之前的耗时，包括缓存核验或底层service |
| `performance.current_call.http_request_count` | 本次处理调用GET/POST次数；缓存命中为0 |

`source_query.mode`区分`network_attempt`（也可能是失败刷新）、`local_snapshot`与`local_rejection`。缓存命中会保留先前service计时，必须配合`cache_hit/current_call`阅读，不能当成本次网络耗时。请求数统计适配器GET/POST调用，不包括urllib内部自动跳转的额外逐跳；记录不保存URL、请求参数、凭据、正文或异常文本。

这些指标不包括Python进程启动/导入、JSON序列化、SDK传输、客户端排队、模型选工具/思考和回复生成。要拆分WorkBuddy总等待，还需要其客户端时间线；本轮没有把未知分钟补成估计值，也未修改全局客户端配置。

原项目249/249正式测试通过（6.959秒），脱敏发布副本249/249通过（6.463秒），零跳过。新增35项覆盖聚合、资源边界、请求计时、MCP快照汇总与CLI；发布初验发现新测试依赖原工作区validation目录，已改用现有`test.helpers.temp_dir`并复跑通过。

未知当前学期时应从学校已选学期或可靠现有上下文确认，不按本机月份猜。当前用户场景的学期已在原报告中明确，不需要另查课程库。

新增代码是`src/service/semester_credits.py`、`src/service/request_timing.py`；接入位于`jwweb_service.py/server.py/models.py`，根目录CLI同步修正。证据位于本机`validation/semester-credit-speed-2026-10-16/`。本轮没有读取真实会话、私人课表或访问学校；真实改选结果与客户端选工具行为仍待一次实操观察。

## 历史第一轮（2026-10-16）：四工具短缓存

用户要求是缩短查询等待，仍按本人权限只读取数。Agent选择在MCP入口给以下四个工具增加60秒、最多32项的进程内缓存：

- `get_grades`：成绩总表。
- `get_grade_details`：成绩组成明细。
- `get_timetable`：按日期查询App课表。
- `get_timetable_web`：按学年学期查询网页课表。

此前每次首页查询都会联网，SQLite成功快照主要用于续页和失败回退。普通成绩需要打开功能页并查询列表；全部明细还逐门读取。App课表本身只有一次请求，本轮没有可证实能删除的首查请求。

相同参数、同账号、同一会话下的成功非空结果可在60秒内复用。更换学期、日期或课程条件分别缓存，最多保留32项；相同范围改变分页大小时驱逐旧变体，避免返回失效游标。只有 MCP 入口应用此策略，底层 service 直接调用不使用这层短时缓存。2026-10-18 已将考试纳入同一契约。

## 怎么用

1. 升级后按 `requirements.txt` 核对项目虚拟环境依赖（本版增加 `python-docx`），随后在 WorkBuddy 重载这个 MCP，让 Python 服务进程和工具描述重新加载。有效来源会话无需仅因升级而重复登录。
2. 直接问“查我指定学期的成绩”“查这周课表”或“查指定学期考试”。普通查总评用 `get_grades`；只有关心平时分、期末分等组成时才用 `get_grade_details`，尽量带具体 `course`。考试使用 `get_exams`。
3. 60秒内问相同条件可复用已有结果。回答应保留来源取得时间，不能把缓存命中说成刚从学校读到。
4. 需要最新数据时说“强制刷新，不使用短时缓存”，客户端应传`force_refresh=true`。该参数只作用于首页；带`cursor`时始终继续读取原固定快照，要重抓必须去掉`cursor`。

日期问题优先使用App课表，学年学期问题优先使用网页课表，不必默认双源并查。查询前也不必每次额外获取能力台账、来源健康。以上是给客户端的路由提示，实际选工具仍由客户端模型决定。

新增的可选输出字段在`freshness`中：

| 字段 | 含义 |
| --- | --- |
| `cache_hit` | `true`表示本次复用了内存结果、没有向学校发起请求 |
| `cache_ttl_seconds` | 短时复用上限，当前60秒 |
| `cache_remaining_seconds` | 命中条目的剩余秒数；非命中时为0 |
| `last_success_at` / `data_age_seconds` | 保留真实来源时间，命中时重新计算年龄 |

有效期不是学校数据实时性的保证。缓存命中不改变`coverage.complete`、快照ID、来源时间或成功时间。

## 账号、失败和并发边界

缓存键包含工具、规范化完整参数、账号和整个本地会话的内存指纹；不增加磁盘凭据副本。换账号、重新登录、注销后不能沿用另一会话结果。等待同工具锁期间发生账号切换，也重新检查上下文。

QueryCache 对相同工具同会话的并发请求合并等待，首个成功后后续可命中；不同工具不共用这把短缓存锁。教务的有状态来源步骤另由会话级激活锁协调；电表只复用独立匿名连接会话，不共享学校身份 Cookie，也不缓存余额结果。没有增加后台轮询、保活或自动登录。

失败、`partial`及空结果不进入这层缓存。强刷之前清理同范围旧内存项，强刷失败仍如实返回原服务的`partial/unavailable`及旧快照边界。命中前核对SQLite当前快照ID和健康状态，不能用已覆盖版本生成续页游标。

## 实测与限制

原项目完整回归214/214通过，零跳过；包括此前193项及新增21项。实际本地stdio发现44工具，四个新输入schema可见；App课表和成绩分别执行首查、命中和强刷，六次输出schema及文本/结构一致性均通过。

脱敏发布副本也214/214通过、零跳过，并通过同样的本地stdio探针；这是当时的本地验证记录，保留原测量条件；不作为当前公开版本的新一次学校实测。

离线性能对照为每次假HTTP固定增加80ms延迟，每阶段测5次，结果为中位数：

| 工具 | 原行为每次联网 | 新版首次取数 | 新版有效期内重复查询 | 5次重复查询上游请求 |
| --- | ---: | ---: | ---: | ---: |
| App课表 | 88.073ms | 93.246ms | 4.130ms | 0（原5次） |
| 成绩总表 | 171.417ms | 176.302ms | 4.355ms | 0（原10次） |

数据来自`validation/query-speed-2026-10-16/benchmark.json`。这证明的是重复抓取被省掉；首查仍受学校响应和网络影响，本轮没有测本人真实学校查询，也未测WorkBuddy模型思考和排队时间。不是线上加速百分比承诺。课表测试采用现有字符串字段样例，额外数值字段兼容性不在本轮验收范围内。

调试中先用测试复现“同一课表发两次请求”，修复后变为一次。独立审查又复现排队换账号泄漏旧结果、并发LRU逐出导致异常两类反例，当前修复及回归均通过；没有将这两类问题留给用户实操排查。

## 维护与复现

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -B -m unittest test.test_query_speed test.test_query_speed_academic test.test_query_speed_concurrency -v
.\.venv\Scripts\python.exe -B -m unittest discover -s test -t .
```

完整测试会创建本地stdio子进程，使用合成会话和临时目录。受限环境应允许本地子进程，不能把跳过stdio记成已验证。

仍慢时先查看实际调用的是总表还是全部明细、是否命中、有没有反复重启 MCP 进程。要最新时用强刷。重启会清空进程内缓存和连接状态，保留原 SQLite 成功快照；需要回滚时使用验证过的完整提交及匹配的项目依赖，再重载 MCP，不再按早期三文件方案局部撤销。不得因此清理真实 data 目录或直接复制正在使用的 WAL 数据库作为完整备份。

## 2026-10-18：当前默认 main 的实现状态

公开 main 提供 47 个注册工具和当前 338 项合成回归对应的实现；本仓库不包含此前开发历史或实验分支。下面的“已实现”指代码、合成反例与本地契约证据，不是全部学校业务已在线验收。

| 项目 | 当前实现与边界 |
| --- | --- |
| P0：教务激活记忆 | 默认开启，`ZJGSU_JW_ACTIVATION_MEMO=0` 可关闭。冷查保留激活 GET；同会话同功能码成功后可跳过。明确 910 或跳过后的可疑空结果补激活并最多重试一次；GET 失败立即停止，不把失败当空结果。会话锁协调同会话跨功能码步骤，未证明学校状态生命周期。 |
| 五工具短缓存 | 成绩、成绩明细、考试及两种课表复用 60 秒内同账号/会话/参数的成功非空结果。`force_refresh=true` 只绕过短缓存，不关闭激活记忆；续页仍消费原快照。 |
| 电表匿名会话复用 | 按表号保留有界、短时匿名连接会话，每次仍读取业务页，不缓存余额、闸位或账单结果。明确失效时丢弃会话；账单/日明细最多重建一次。配置迁移的既有非空定位矛盾在取源前拒绝，这不证明设备所有权或数据实时性。 |
| TLS 与本地存储 | SSLContext 复用保留证书及主机名校验，不等于 urllib 已有 HTTP 连接池。存储采用 WAL+FULL，并将选定成功快照/健康记录合并事务；未采用 NORMAL 的掉电耐久性取舍。维护 CLI 提供一致备份、checkpoint 与状态查看，拒绝同源目标、默认不覆盖已有目标。 |
| 通用 CLI、brief、工具描述精简 | 尚未交付。学分专用脚本与缓存库维护 CLI 不等于通用直查通道；后续是否增加需根据实际客户端时间线决定。 |

调用数需按路径阅读：冷查通常 GET+POST；激活记忆命中可只发 POST；短缓存命中为零来源请求；触发补激活会增加请求。不要把历史两请求探针、某次学校样本或一个工具调用统一解释为当前固定请求数。

新的性能报告包含实施方少量真实接口观测。本轮独立验证的是合成行为、请求次数与回归，没有重新进行学校网络 A/B，也没有测 WorkBuddy 从提问到回答的全过程。`handler_ms` 不含模型选工具、思考、客户端排队、进程启动和回复生成；缓存中旧 `source_query` 计时不是本次联网耗时。不承诺“缩短到四分之一”或固定端到端秒数。

余座仍默认拒绝明文 HTTP Cookie 并提供官方人工入口；不得为提速启用不安全日常抓取。本人借阅取消，校园卡及畅约相关入口仅简介与人工导航；只读、无后台保活的边界不变。最新范围见[当前成果](release-status.md)和[限制清单](limitations.md)。
